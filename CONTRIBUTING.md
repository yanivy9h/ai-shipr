# Contributing to AI-SHIPR

Thanks for your interest in AI-SHIPR. This repo is a working product operating system for product managers — a harness for PMs on top of LLMs. It's meant to be cloned, populated, and run on real product work.

Contributions are welcome, whether that's a bug report, a clearer template, a new skill or agent, or a fix to the docs.

## Ways to contribute

- **Report a problem** — something in the system is unclear, broken, or doesn't behave as the docs describe. Open an issue using the Bug report template.
- **Suggest an improvement** — a new agent, skill, workflow, or playbook; a better folder convention; a sharper template. Open an issue using the Feature request template first so we can align before you build.
- **Improve the docs** — README, the Setup Worksheet, agent/skill definitions, or the Duolingo example. Small fixes can go straight to a PR.

## Submitting changes

1. Fork the repo and create a branch from `main`.
2. Keep changes focused — one logical change per pull request.
3. Match the existing tone and structure. AI-SHIPR files are direct, structured, and free of hype or filler. New skills/agents should follow the format of the existing ones in `A-AI/`.
4. If you add or change a skill, agent, workflow, or playbook, update the relevant tables in `README.md` and `CLAUDE.md` so the system stays in sync.
5. Open a pull request using the PR template and describe what changed and why.

## What doesn't fit here

This is a single-author product, not a large open-source platform. Big structural rewrites or changes to the core SHIPR model (Strategy · Hypotheses · Initiatives · Proof · Relationships) are best discussed in an issue before any code is written.
