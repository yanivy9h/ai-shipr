Three additions in this update: multi-product support via lead mode, the Handoff-Builder skill (two modes), and the EOD workflow.

## 1. Multi-Product Support (Lead Mode for Solo PMs)

### What changed

A question that comes up frequently in workshops: what do you do when you are one person managing more than one product?

The previous answer was: create two separate AI-SHIPR folders, one per product. That still works and is the right call when the products are completely unrelated.

But when products share stakeholders, budget, or engineering resources — or when you need a cross-product view of your priorities — the separate-folder approach has a gap. You can't ask "which product deserves my attention this week?" in a session that only sees one product.

Lead mode solves this.

### Lead mode for solo PMs — what it is

Lead mode was originally designed for VPs managing teams of PMs. The same structure works for one person managing multiple products. The key insight: the system doesn't care whether "team" means other people or other products. It reads the same files either way.

### How it works

```
products/
├── shared/                   ← cross-product layer (you maintain this)
│   ├── Constraints.md        ← shared capacity, budget, rules that span both products
│   ├── Stakeholders.md       ← stakeholders who touch both products
│   └── Portfolio-Roadmap.md  ← cross-product sequencing (Portfolio-Strategist writes this)
│
├── product-a/                ← full AI-SHIPR instance
│   ├── CLAUDE.md             ← reads ../shared/ first, then local strategy files
│   ├── Settings.md           ← team_mode: individual
│   └── [full AI-SHIPR structure]
│
└── product-b/                ← same structure
    ├── CLAUDE.md
    ├── Settings.md
    └── [full AI-SHIPR structure]
```

Each product folder runs as a full AI-SHIPR instance. Before reading local files, it reads `shared/` — so org-level constraints and cross-product stakeholders are always in scope.

### What this unlocks

- **Portfolio-Strategist** becomes available — answers "which product deserves attention this quarter?" with structured tradeoff analysis
- **`/today`** in a lead-mode root session aggregates across both products
- **Shared stakeholder context** — a stakeholder who touches both products is filed once and visible from either session
- **Shared constraints** — engineering capacity and budget are defined once and flagged in both product sessions when relevant

### When to use it vs. separate folders

| Situation | Recommendation |
|-----------|---------------|
| Products are completely unrelated (different company, different domain) | Separate folders |
| Products share stakeholders, budget, or engineering | Lead mode |
| You want a portfolio view — "where should I focus this week?" | Lead mode |
| You are early and just want to get started without complexity | Separate folders — upgrade later |

### How to set it up

1. In Settings.md, set `team_mode: lead`
2. Create the folder structure above
3. In each product's CLAUDE.md, add `../shared/` to the Session Start read list (before local strategy files)
4. Run the Setup Worksheet — Part 7 (Portfolio) captures the cross-product context
5. Run Populate-Strategy — it now generates `shared/` layer files in addition to per-product strategy layers

### What changed in the Setup Worksheet

The worksheet now handles both single-product and multi-product setups:

- **Parts 1-3** (Product, Strategy, Constraints) repeat per product. Each product gets its own section.
- **Part 4** (Your Role) has two new questions: time split across products and how the products relate to each other.
- **Part 5** (Stakeholders) now includes a "product relevance" field — mark each stakeholder as Product A, Product B, or Cross-product.
- **Part 6** (Users) repeats per product.
- **Part 7** is now "Your Portfolio" for solo PMs managing multiple products. The old "Your Team" section for VP/team leads is now **Part 8**.

## 2. Handoff-Builder Skill

### What it is

Handoff-Builder is a single skill with two modes. The skill lives in `A-AI/AI-Skills/Handoff-Builder.md`.

### Mode 1: EOD (End of Day)

**When to use:** At the end of any working session, before you close Claude Code.

**What it does:** Reads your active initiatives, recent meeting notes, and open hypotheses, then generates a structured summary with four sections:

- **Done today** — what was completed, decided, or closed (including any hypothesis outcomes)
- **In progress — resume tomorrow** — current state and the exact next step for each active item
- **Blocked** — what is stuck, who the blocker is, and the specific ask needed to unblock it
- **Waiting on others** — what is pending, who owns it, and what happens if it slips

Closes with a **Quick-start for tomorrow**: three bullets that tell you exactly where to pick up, with no re-orientation needed.

**How to invoke:** Type "EOD handoff" or "create an EOD" in your Claude Code session.

**Why it matters:** Claude has no memory between sessions. Anything that exists only in chat is gone when the session ends. An EOD handoff writes your state to a file — so the next session starts from where you left off, not from zero. It is the single fastest way to eliminate the "re-explaining everything" tax that kills AI productivity over time.

### Mode 2: Handoff (Ownership Transfer)

**When to use:** When someone else is covering your work — a colleague, a delegate, or a PM stepping in while you are away.

**What it does:** Generates a decision-ready brief for the person picking up your work:

- **What you are picking up** — 2-3 sentence context brief
- **Active initiatives** — table with current stage, status, and the first action the new owner should take (not "review it" — a specific next step)
- **Decisions you may need to make** — pending decisions with context, options, and your current recommendation
- **Blockers requiring your attention** — specific asks with deadlines
- **Key relationships** — stakeholder table with current dynamic and what each person expects during the coverage period
- **What NOT to touch** — protects in-flight work from being re-opened or re-decided

Closes with instructions for how to use the AI-SHIPR system during the coverage period.

**How to invoke:** Type "create a handoff for [name or role]" — for example, "create a handoff for Sarah" or "create a handoff for the covering PM."

### The difference between EOD and Handoff

| | EOD | Handoff |
|--|-----|---------|
| Audience | Yourself, tomorrow | Another person |
| Tone | Direct, personal | Instructional, context-rich |
| Scope | Today's work | Full initiative portfolio |
| Filed where | `O-Output/` or chat | Share with recipient + file |
| When to run | End of every session | Before handing off ownership |

### Skill chain

Handoff-Builder is typically the last skill run in any session. A natural closing chain:

```
[any skill run during the session] → Handoff-Builder (EOD)
```

Or at the end of a sprint:

```
Sprint-Summarizer → Handoff-Builder (Handoff for the covering PM)
```

## What to do with this update

**If you are a solo PM running one product:** nothing changes. The worksheet still works the same way. Skip Parts 7 and 8.

**If you are managing multiple products:** fill Parts 1-7 of the updated worksheet, set `team_mode: lead` in Settings.md, and follow the folder setup above.

**Everyone:** add Handoff-Builder to your daily rhythm. Run "EOD handoff" at the end of every session. It takes two minutes and eliminates the re-orientation tax from the next session.
